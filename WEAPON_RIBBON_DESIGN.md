# Оружейная лента: реализованный интерфейс

11.10.2026. Quick Access **1.7.30** предоставляет данные; YZE Combat: Permission Fix + Action Widget **1.5.0** показывает ленту и выполняет операции. Основной виджет сохраняет компактные действия, сворачиваемые слоты и памятку.

## Размещение и порядок

По умолчанию лента — независимая перемещаемая область. Клиентская настройка позволяет пристыковать её сбоку или снизу. У края экрана область ограничивается окном; на узком экране группы переносятся, подробности прокручиваются внутри. При полном сворачивании виджета лента скрывается; явное «Закрепить» оставляет независимую ленту видимой.

Один удерживаемый Item занимает одну строку, включая двуручный хват. Карточки рук в основном виджете убираются только при наличии совместимой новой ленты; старые версии Quick Access сохраняют прежний интерфейс.

| Группа | Содержание | Визуальный приоритет |
| --- | --- | --- |
| Идентификация | Л/П/2Р, изображение, название, сломано | Название выделено; хват — отдельная кнопка. |
| Атака | Бонус, урон, дальность, бронепробитие с оператором, артефакт | Подпись над значением; стабильный порядок. |
| Боеприпасы | Текущие патроны/ёмкость или базовая перезарядка | Отделена границей; патроны выделены янтарным. |
| Свойства | Два названия со значениями, затем +N | Спокойные компактные кнопки; описание раскрывается по нажатию. |
| Команды | Атака, Зарядить, Дозарядить | Отдельная группа кнопок; форма открывается только для выбранного действия. |
| Незавершённая работа | Прогресс зарядки и восстановление операции | Счётчик плюс полоса; неопределённый результат требует явной проверки. |

Поля без данных скрываются. Свойства следуют Item и публичному API FL Firearms, а не копии каталога. Описание приходит как обычный текст; журнал Rich Info Tooltips и его страница должны быть доступны наблюдателю. Секретные страницы не раскрываются.

## Атака

Цена выбирается явно. Затем открывается штатный диалог Forbidden Lands, оформленный RDP при его включении. Открытие/закрытие до броска бесплатно; стоимость резервируется при submit. Точная метка операции связывает бросок с ChatMessage. Дублирование submit/подтверждения и Push не оплачиваются повторно. FL Firearms самостоятельно расходует патрон и учитывает свои механики.

## Зарядить и дозарядить

Игрок видит **Прогресс**, **Всего**, **За действие** и **Единицы** (шаги/секунды). Например, 0/4, за действие 2: первая операция даёт 2/4, следующая — 4/4. Каждая операция имеет свою выбранную цену; прогресс переживает смену раунда и перезагрузку.

Ускоряющие способности учитываются вручную изменением общей длительности или величины шага. Базовое поле Item служит подсказкой, а не автоматическим распознаванием талантов. Для секунд нет фонового таймера.

«Сохранить прогресс вручную» меняет только счётчик, бесплатно и без патронов. Даже сохранение полного прогресса не вызывает зарядку: игрок явно выполняет завершение, при необходимости с нулевым шагом.

Для MAG на завершающем шаге вызывается публичный loadMagazine (заполнить магазин) или topOffMagazine (добавить один патрон, только при свойстве TopOff). Выбор подходящего ресурса и действительный расход остаются FL Firearms. В 0.4.6 результат void проверяется по точному состоянию нормализованного магазина; в 0.4.7 используется структурированный результат.

Для немагазинного огнестрела и обычного оружия с медленной перезарядкой доступен ручной прогресс. Универсальный флаг «заряжено» и расход стрел не выдумываются; эти механики остаются ручными или системными.

## Согласованность и сбои

Quick Access владеет слотами/руками, FL Firearms — магазином/боеприпасами, виджет — прогрессом, оплатой и журналом операции. Журналы оружия и экипировки используют одну очередь на Actor у активного GM. Права, Item, ревизии, бой/раунд повторно проверяются перед работой. Платные действия требуют активного GM.

Если показанное оружие, прогресс или раунд изменились при открытой форме, выбор сбрасывается с объяснением. Незавершённая операция блокирует новые манипуляции и ручные отметки виджета, сохраняя просмотр.

У публичного API FL Firearms нет внешнего ключа идемпотентности. Перед вызовом сохраняется фаза external; потерянный ответ не вызывает повторную загрузку. Игрок проверяет магазин и ресурс, затем выбирает «Зарядка выполнена» либо «Не выполнена». Только после явного определения результата доступно продолжение/отмена. Завершённая зарядка не получает автоматический откат расхода ресурса.

Foundry не предоставляет общей транзакции Actor, Active Effects и чужого API. Внешние макросы/ручные GM-записи не входят в очередь; конфликт требует проверки. Повреждённые журналы могут потребовать GM. Проверки покрывают Documents в стенде; живой многоклиентский мир остаётся приёмкой.
